ABSTRACT

The FieldAssist System is a web-based application designed to help commercial FMCG and consumer packaged goods enterprises streamline secondary distribution, field representative monitoring, and automated retail order booking. It is built using React 19 and TypeScript for dynamic user interface management, Tailwind CSS for styling, Leaflet and OpenStreetMap for interactive geospatial positioning, Vercel Serverless micro-services for backend routing, and Supabase (PostgreSQL) paired with local storage for permanent data persistence. The application runs responsively in standard desktop and mobile web browsers.

The application features five primary operational modules: a Live GIS Fleet Tracking Radar, a Retail Store Directory with Credit Scoring, a Dynamic Product Inventory Catalog with Stock Level Alerts, an Atomic Secondary Order Booking Engine, and an Automated Geofence Verification and Beat Plan System. The user enters or inspects operational values such as retailer coordinates, order SKU case quantities, pricing, and GPS check-in pings, and the live status is presented on the interactive dashboard.

The system does not rely on costly proprietary mapping APIs (such as Google Maps), black-box machine-learning predictors, or vendor-locked proprietary mobile SDKs. Representative locations are acquired through the browser’s standard HTML5 Geolocation API backed by multi-tier IP/network fallback, and map rendering is handled directly by public OpenStreetMap raster tiles. The numbers and data instances provided in this report are examples and illustrative operational records. The system is engineered to provide transparent, hand-checkable calculations, permanent cloud synchronisation, and uninterrupted offline capability.

1. INTRODUCTION

In fast-moving consumer goods (FMCG) and retail distribution networks, manufacturers and primary distributors supply products to retail stores through on-ground sales representatives. The effectiveness of this secondary distribution channel depends on regular store visits, accurate order booking, disciplined beat schedule execution, and transparent inventory tracking. Traditionally, sales representatives record retailer orders on physical paper books, call distributors over the phone, and submit manually compiled end-of-day visit logs. This paper-bound workflow introduces transcription errors, delayed order dispatches, stock-outs at retail counters, and a general lack of operational visibility for regional sales managers.

Our project, the FieldAssist System, is a web application that runs responsively in a browser.

The user enters and inspects field records, and the system processes order totals, distance matrices, geofence compliance, and stock updates in real time. The dashboard has modular sections for fleet telemetry, retail store management, inventory catalogs, and order booking. Each module provides interactive data views, search filters, form validation, and feedback messages. The calculations use transparent arithmetic formulas, so the application does not rely on opaque AI models or hidden algorithms.

The system is needed because regional sales managers often want to verify whether field representatives physically visited their assigned retail outlets, track rep battery and live coordinates, prevent fraudulent check-ins, inspect retail debt exposure, and monitor secondary sales order volumes against assigned monthly targets. Sales executives also need an immediate tool to browse live catalog prices, calculate bulk order values with tax, and book orders directly at the retail storefront. Our system gives all of these in one browser-based interface.

The scope of the project is focused on secondary sales operations, geospatial tracking, and retail order workflows. It does not include primary factory ERP manufacturing batch management, hardware laser barcode scanners, or credit card payment processing. The telemetry and geofence results depend on browser geolocation permissions and user-submitted data.

2. LITERATURE REVIEW

2.1 Background study

Secondary sales force automation systems have been widely investigated in enterprise supply chain literature. In traditional field distribution, route coverage is planned using fixed beat schedules where a representative visits a predefined set of retail counters on specific weekdays. Prior studies indicate that paper-based order management leads to order latency of up to 48 hours, inventory discrepancies between stockists and retailers, and lack of accountability regarding representative route adherence.

Modern digital solutions introduce mobile sales force automation (SFA) to capture orders electronically and transmit them directly to warehouse databases. However, many existing commercial SFA systems suffer from two major drawbacks: high operational recurring costs caused by proprietary mapping APIs (such as Google Maps Platform per-request billing), and brittle offline behavior that fails when field executives enter dense urban markets or rural zones with poor network connectivity.

An open-source geospatial approach suits this project because public raster tile providers (such as OpenStreetMap) coupled with lightweight client-side mapping engines (Leaflet) eliminate third-party API keys, billing thresholds, and vendor watermarks. At the same time, computing distance between coordinates using the standard Haversine formula ensures mathematical transparency and allows managers to verify geofence boundaries without complex external GIS software.

In terms of system reliability, client-side validation must check required form fields, non-negative quantities, phone number structures, and valid geographic coordinates before transmitting requests. By implementing a hybrid three-tier persistence layer (Supabase PostgreSQL cloud database, Vercel Serverless micro-services, and browser local storage fallback), the system ensures uninterrupted data entry even during intermittent network disconnections.

The technologies we selected are suitable for a modern web application deployed on cloud edge infrastructure. React 19 provides component-based UI rendering, TypeScript guarantees compile-time type safety, Tailwind CSS ensures responsive layout styling, Leaflet renders interactive maps, Vercel serverless functions handle API requests, and Supabase provides managed PostgreSQL storage.

3. MOTIVATION, PROBLEM STATEMENT AND OBJECTIVES

3.1 Motivation

Field distribution and secondary order logistics form the backbone of commercial trade across India and developing economies. Sales managers, distributor stockists, and retail shopkeepers frequently face routine questions: has the beat sales rep visited the store today, how much stock remains in the local depot, what is the outstanding credit balance of the retailer, and how close is the team to reaching its monthly sales quota? Answering these questions manually requires repeated phone calls, paper ledgers, and fragmented WhatsApp messages, where human error can lead to delayed deliveries or lost revenue.

As students of computer science and engineering, we wanted to turn this repeated manual workflow into a robust, cloud-enabled web application. Another motivation was practical learning: building FieldAssist gave us an opportunity to integrate React 19, TypeScript, Tailwind CSS, Leaflet geospatial mapping, Vercel Serverless micro-services, and Supabase cloud PostgreSQL into a cohesive, production-grade project. We also wanted to engineer a system that shows its operational logic openly, allowing field managers to audit every calculation and geofence verification without treating the system as a mysterious black box.

3.2 Problem statement

Distributors and sales managers need a reliable, cost-free method to track field sales force operations, verify on-ground store visits, manage retailer credit exposure, and process secondary sales orders in real time. Conducting these operations manually on paper or through disjointed spreadsheets is slow, error-prone, and susceptible to proxy check-ins where field reps claim visits without traveling to the outlet. The problem addressed by this project is to provide a unified web interface that automates order collection, calculates order values consistently, enforces physical geofence verification, and persists data permanently to cloud storage.

The system centralises operational tasks into one interface, eliminates paper order transcription, and provides visual GIS telemetry. It can be used by small-to-medium consumer goods companies, wholesale stockists, and classroom demonstrations. However, it relies on browser-accessible GPS coordinates and user-submitted data, and it does not interface directly with legacy mainframe manufacturing ERP systems, automated vehicle OBD sensors, or physical credit card swipe machines. It is therefore designed specifically for secondary sales automation and route monitoring.

4. SYSTEM ARCHITECTURE

4.1 Architecture overview

The system follows a modern decoupled client-serverless architecture: the user interacts with the React 19 single-page application in the browser, client-side actions trigger asynchronous REST requests to Vercel Serverless micro-services, Python/TypeScript backend handlers validate and query Supabase PostgreSQL, map tiles are fetched directly from OpenStreetMap servers, and updated state is rendered dynamically.

Figure 1: System architecture and request-response flow

4.2 Layers of the architecture

The architecture consists of three robust layers:

Presentation Layer (Client-Side Browser): Built with React 19 and Tailwind CSS, this layer renders interactive views including the live Leaflet map canvas, inventory tables, order entry forms, and analytical KPI cards. It manages local UI state and captures hardware geolocation coordinates.

Application & API Layer (Vercel Serverless Functions): Decoupled micro-service endpoints located in /api/* receive REST HTTP requests, execute input validation, calculate Haversine distances, process order line-totals, and enforce data schema integrity.

Data & Persistence Layer (Cloud & Offline Hybrid): Primary storage resides in Supabase cloud PostgreSQL with Row Level Security (RLS) policies. When offline, the client automatically falls back to an internal browser localStorage cache, guaranteeing that entered orders and logs are never lost.

6. METHODOLOGY

6.1 Development approach

We followed an iterative Agile development methodology. We began by identifying the operational requirements of FMCG field sales operations: live rep positioning, store check-in verification, SKU cataloging, and order booking. Next, we designed relational database tables in Supabase PostgreSQL, established decoupled Vercel Serverless micro-services, and built user interface components using React 19 and Tailwind CSS. OpenStreetMap tiles were integrated using Leaflet, and a robust three-tier offline persistence mechanism was engineered to ensure zero data loss.

6.2 Working of the system

The system functions as follows:

1.    The sales executive or manager logs in via the browser and selects their operational view (Live Tracking, Products, Orders, or Retailers).
2.    On opening the Live Tracking Radar or Products Map, the browser prompts for GPS location access. The multi-tier geolocation service locks the real hardware GPS coordinates.
3.    When a sales rep checks into a store, the system calculates the Haversine distance between the rep's coordinates and the store's registered latitude and longitude.
4.    If the distance is within 100 meters, the visit is authenticated as "Geofence Verified". If greater, a visual advisory warning is logged.
5.    During secondary order booking, the representative selects SKU codes and case quantities; unit pricing, case multipliers, and tax rates are calculated instantly, and the order is permanently saved to Supabase cloud PostgreSQL.

6.3 Frontend and backend

On the frontend, modular React 19 components render data tables, modals, interactive Leaflet maps, and real-time KPI cards. Tailwind CSS provides structured dark-theme styling, while Framer Motion handles modal animations. On the backend, Vercel Serverless Functions (Node.js 24) receive requests, validate data payloads, and execute atomic CRUD operations against Supabase.

6.4 Formulas and units

Distance is measured in meters (m) or kilometers (km), currency in Indian Rupees (₹), and stock in whole case packs. The mathematical formulas used in the system are defined in Table 5.

Table 5: Formulas and units
Quantity Formula Notes
Haversine Distance (d) d = 2R · arcsin(√(sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2))) R = 6371 km (Earth radius); calculates distance between coordinates.
Geofence Compliance Status = (d ≤ 100 m) ? "Verified" : "Outside Boundary" 100-meter radius threshold for retail storefronts.
Order Item Total Total = Quantity (Cases) × Case Pack Size × Unit Price Total price per line item before applicable taxes.
Order Net Total Net = ∑ Total_i × (1 + TaxRate_i / 100) Sum of all line items plus applicable GST rate.
Monthly Target % Target Achieved % = (Sales Amount / Monthly Target) × 100 Calculates sales quota fulfillment for representatives.

6.5 Data handling and validation

The application validates all inputs on both client and server: order case counts must be positive integers, retailer names and addresses cannot be blank, phone numbers must adhere to national formatting, and GPS coordinates must fall within realistic geographic boundaries. Erroneous values generate descriptive error toasts, preventing corrupt database writes.

6.6 Testing approach

Testing was conducted across normal, boundary, and invalid inputs for every module (see Chapter 8). Test cases were verified against hand-calculated values, and live database responses were benchmarked directly on the production Vercel deployment.

07 Disconnect internet and book a new order. Order saved permanently to local storage cache.
08 Reconnect internet and trigger cloud sync. Local records sync permanently to Supabase DB.
09 Query backend health endpoint (/api/health). Returns HTTP 200 with supabase-permanent status.

8.6 Strengths and limitations

Strengths: The system utilizes 100% open-source GIS mapping (OpenStreetMap & Leaflet), eliminating expensive Google Maps billing. The 3-tier persistence architecture guarantees zero data loss during network dropouts, and the interface is fully responsive.

Limitations: Location accuracy is subject to hardware GPS sensor limits and indoor signal attenuation. The application does not interface directly with physical barcode guns or legacy SAP mainframe ERP systems.

9. CONCLUSION AND FUTURE SCOPE

9.1 Conclusion

The FieldAssist System demonstrates how a modern, decoupled web architecture can solve core challenges in secondary field sales operations. Built with React 19, TypeScript, Leaflet, OpenStreetMap, Vercel Serverless Functions, and Supabase cloud PostgreSQL, the platform provides automated retail order booking, live GPS fleet radar tracking, mathematical geofence verification, and reliable offline data persistence. Its modular architecture eliminates commercial API fees while delivering an enterprise-ready user experience for field representatives and sales executives alike.

This project enhanced our engineering understanding of full-stack TypeScript development, asynchronous serverless routing, relational database design with Row Level Security, geospatial mathematics, and client-side offline storage mechanisms.

9.2 Future scope

The system can be extended in the following directions:

1.    Integrate traveling salesperson problem (TSP) algorithms for automated daily beat route optimization.
2.    Package the web application as a Progressive Web App (PWA) with background geolocation sync workers.
3.    Add optical character recognition (OCR) and camera barcode scanning for instant retail shelf auditing.
4.    Connect UPI QR-code and digital payment gateways for instantaneous spot collections.
5.    Support automated PDF invoice generation and WhatsApp Business notification dispatches.
6.    Implement Bluetooth thermal printer drivers for on-the-spot physical receipt generation.
7.    Introduce machine learning demand forecasting models once multi-year secondary sales datasets accumulate.
